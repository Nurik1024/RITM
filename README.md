# Ритм

Личный календарь привычек: выбери дни недели, отмечай выполнения и собирай опыт. Несколько привычек, месячная статистика, уровни и достижения доступны в одном аккаунте на разных устройствах.

## Правила

- У каждой привычки своё недельное расписание, которое повторяется в следующих месяцах.
- Отметки можно добавлять и менять только за сегодня и вчера в часовом поясе аккаунта.
- Дни отдыха не входят в месячный план. Даты до создания привычки не считаются пропусками.
- Процент месяца — выполненные запланированные действия / весь план месяца. Будущие действия ещё не выполнены, но не считаются пропусками.
- За одно выполненное действие начисляется 25 XP. Повторная отправка той же отметки не добавляет опыт. Отмена выполнения пересчитывает опыт.
- Пропуски сохраняются в истории и не удаляют общий прогресс. Архивирование привычки сохраняет её историю.

## Стек и данные

React + Vinext, Cloudflare Workers, Cloudflare D1 и Drizzle. Вход — встроенный Sign in with ChatGPT на платформе Sites. Рабочая база находится отдельно от Git-репозитория. Данные привязаны к идентификатору вошедшего пользователя, а не к адресу электронной почты.

**GitHub хранит исходный код. GitHub Pages не запускает сервер этого приложения.** Для аккаунтов, защищённого API и синхронизации нужны поддерживаемая серверная среда и база. Текущая интеграция входа рассчитана на Sites; перенос на другого хостера требует отдельной интеграции провайдера авторизации и проверки доступа.

## Локальный запуск

Нужны Node.js 22.13+ (рекомендуется 24), npm, Git и tar.

```sh
npm ci
npm run db:generate
npm run build
```

После первой сборки примените каждую **ещё не применённую** миграцию из `drizzle/` по порядку. Пример команды (замените имя файла фактическим):

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_example.sql
npm run dev
```

Откройте адрес Local из вывода сервера. В режиме portable на loopback-адресе `/signin-with-chatgpt?return_to=/` включает тестовый аккаунт. Это локальная имитация входа; в production вход обслуживает Sites. Локальная база и рабочая база независимы.

Независимые сценарии проверки расписания, статистики, часовых поясов и опыта:

```sh
node --test scripts/product-test.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
```

## Публикация и GitHub

Конфигурация Sites находится в `.openai/hosting.json`, схема — в `db/schema.ts`, миграции — в `drizzle/`. Сохраните миграции вместе с исходниками. Не меняйте уже применённые миграции; создавайте следующие.

Публикация выполняется через Sites с точным коммитом исходников и результатом сборки. Сам по себе push на произвольный GitHub-репозиторий не обновляет текущий сайт. Для отдельной копии у другого владельца зарегистрируйте новый Site и используйте его идентификатор; не присваивайте чужой Site своему проекту.

Перед загрузкой в GitHub проверьте `git status` и список файлов. `.gitignore` исключает зависимости, локальную базу, `.env*`, `.dev.vars*`, ключи PEM, внутреннее состояние инструментов и сборки. Не добавляйте их принудительно. Если секрет когда-либо попал в коммит, отзовите его; удаления из последнего файла недостаточно.

## Безопасность

- Приложение не получает и не хранит пароли ChatGPT; в базе нет собственных паролей или их хешей. Сессии входа обслуживает провайдер. Это не отдельная регистрация по почте и паролю.
- Защита самого входа от перебора паролей и MFA относятся к провайдеру авторизации. Их настройки не реализуются в этом репозитории.
- Сервер должен проверять авторизацию, владельца каждой записи, Origin изменяющих запросов и формат входных данных. Ограничения по датам и расчёт XP должны соблюдаться сервером, независимо от браузера.
- SQL-запросы используют параметры; пользовательский ввод не должен собирать текст SQL.
- Прикладные секретные API-ключи для основной работы не требуются. Если появятся внешние интеграции, храните ключи в серверных секретах хостинга, а не в исходниках и переменных, доступных браузеру.
- GitHub-репозиторий не является резервной копией пользовательской базы. Резервное копирование и восстановление D1 настраиваются отдельно.

Проверки приложения не заменяют независимый аудит безопасности и не гарантируют отсутствие всех уязвимостей. При открытии сайта широкой аудитории отдельно проверьте доступ, мониторинг, ограничения запросов и восстановление данных.

## На iPhone

Откройте опубликованный сайт в Safari → «Поделиться» → «На экран “Домой”». Если есть переключатель «Открывать как веб-приложение», включите его. На домашнем экране появится иконка Ритма. Для входа и синхронизации нужен интернет; это не обещание автономного режима или push-уведомлений.
